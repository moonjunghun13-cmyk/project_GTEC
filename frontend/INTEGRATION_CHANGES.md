최신 작업 폴더는 `GTEC-frontend-upload`, Git 브랜치는 `frontend-new`입니다. 아래 11월 19일 기록보다 이 절의 내용이 우선합니다. Java 백엔드와 Python AI 소스는 수정하지 않았습니다.

- 관리자 관리 화면의 글자·간격·목록/상세 스크롤을 정리했습니다. 기존 대시보드 배치를 유지하고 상품·주문·회원·리뷰 검색에 확인 버튼과 Enter 검색을 추가했습니다.
- 상품 목록은 전체 너비의 카드 목록으로, 클릭한 상품은 전체 너비 편집 화면으로 표시합니다. 상세 진입 후에도 기존 카테고리·판매 상태·정렬 드롭다운과 선택값을 유지합니다. 저장·판매중지 버튼은 오른쪽에 정렬하고 판매중지는 빨간색으로 표시합니다.
- 상품 저장 payload와 판매 상태 정렬을 수정하고 상품 삭제 동작을 판매중지/재개로 바꿨습니다. 대표 이미지·추가 이미지 등록/제거 UI와 개발용 파일 업로드를 추가했습니다. 기존 상세 스펙·이미지·120개 상품·호환성 팝업은 유지합니다.
- 관리자도 쇼핑몰에서 구매·찜·장바구니·본인 주문 기능을 사용할 수 있도록 했습니다. 관리자 화면 접근 권한은 유지합니다.
- 화면의 별점과 별점 정렬/필터를 제거했습니다. 리뷰 관리와 분석을 합치고 분석 대기 카드·필터·배지를 제거했습니다. 긍정·부정 비율은 분석 완료 리뷰 기준이며, 결과가 없는 리뷰를 임의로 긍정/부정으로 만들지 않습니다.
- FAQ 검색창을 넓히고 중복 제목을 제거했습니다. 대시보드의 관리자 이용안내 4개를 관리 화면에서도 같은 데이터로 표시하며 분류·질문·펼치기 열을 정렬했습니다. FAQ 등록/수정/삭제 창과 POST/PUT/DELETE 호출, 오류 시 입력 보존을 추가했습니다.
- 주문 화면에 토스 카드·간편결제 위젯과 약관을 표시합니다. 카드 선택 시 `CREDIT_CARD`로 주문을 요청하고 기존 결제 승인 API를 사용합니다. 카드사·할부 목록과 버튼 활성화를 확인했습니다.

## 현재 남아 있는 제약

- FAQ 쓰기: 로그인은 JWT를 발급하지만 FAQ 쓰기 컨트롤러는 별도 HttpSession 관리자 로그인을 요구합니다. 실제 관리자 요청에서 HTTP 401을 확인했습니다. UI/API 연결은 있으나 서버 등록·수정·삭제 성공을 보장하지 않습니다. 고정 관리자 이용안내의 편집 진입은 내용을 채운 편집창을 열며 저장 시 고객 FAQ의 새 글로 요청합니다. 원본 가이드를 서버 게시글로 가장하지 않습니다.
- 별점 없는 신규 리뷰: 현재 서버의 신규 리뷰 DTO는 rating을 필수로 요구합니다. 프론트는 임의의 점수를 넣지 않으므로 이 서버 제약이 해결되기 전까지 신규 리뷰 저장이 제한됩니다. 기존 리뷰 수정은 서버에 저장된 기존 rating이 있을 때만 유지합니다.
- 결제: 테스트 환경입니다. 실제 결제 승인까지 검증하지 않았습니다. 공용 샘플 키의 DEFAULT 위젯은 퀵계좌이체 항목을 표시하며, 현재 화면에서 해당 항목을 숨기지는 못했습니다. 프론트는 계좌이체·가상계좌 결제 진행을 차단합니다. 상점 위젯에서 해당 수단을 제외한 설정이 필요합니다.
- 파일 업로드: Vite 개발 서버의 `/__frontend/product-images`가 파일을 `public/storefront/uploads`에 저장합니다. 운영 정적 배포에는 별도 업로드 저장소/API 연결이 필요합니다. 이 런타임 폴더와 검증 이미지는 Git에 포함하지 않습니다. 기존 상품에 연결된 이미지를 제거하는 것은 연결 해제이며 원본 파일의 물리 삭제가 아닙니다.

## 남은 서버·운영 설정 사항

1. **추천 재학습의 오류 상태 전달**: 구매 학습 기록이 없을 때 Python의 422 응답이 Java Gateway에서 일반 500 ‘서버 내부 오류’로 전달됩니다. 백엔드는 수정하지 않았습니다. 프론트는 준비도 `ready=false`를 먼저 확인해 최신화를 보류합니다.
2. **학습 데이터 부족**: 별도 연동 DB에는 실상품만 등록했고 구매 이력을 만들지 않았습니다. 추천·고객 모델 재학습을 완료했다고 표시하지 않습니다. 고객 모델은 원래 구현대로 조건과 검증 개선이 있을 때 후보만 저장하며 운영 모델을 자동 교체하지 않습니다.
3. **FAQ 쓰기 인증 불일치**: JWT 관리자로 로그인해도 FAQ 쓰기의 HttpSession 검사와 맞지 않습니다. 백엔드 수정 없이 프론트만으로 관리자 세션을 만들 수 없어 조회 전용입니다.
4. **결제 설정**: 토스 위젯용 공개 테스트 클라이언트 키를 이 프론트에 제공받지 않아 실제 결제창·승인·환불까지 시험하지 않았습니다. 비밀키를 프론트에 넣지 않았습니다.
5. **운영 배포**: 현재 URL은 이 PC의 Vite 개발 서버입니다. 정적 배포 시에도 `/api`, `/oauth2`, `/login/oauth2`를 Java 서버로 연결하는 운영 프록시가 필요합니다.

## 실행 환경과 데이터

기존 `gtec` DB는 보존하고 **별도 `gtec_example_integration` DB**를 사용했습니다. 새 백엔드가 자체 기본 스키마 설정으로 이 DB를 초기화했고 실상품 120개만 정식 상품 API로 등록했습니다. 기존 회원·주문 이력을 복사하거나 더미 구매 데이터를 생성하지 않았으므로 초기 분석 수치는 0입니다.

| 서비스 | 포트 |
| --- | --- |
| 새 경로 프론트 | 5175 |
| 새 경로 Java 백엔드 | 8093 |
| 새 경로 고객 분석 FastAPI | 8201 |
| 새 경로 추천 FastAPI | 8202 |
| 새 경로 리뷰 분석 FastAPI | 8203 |

제공된 CMD 명령과 동일한 `python -m uvicorn main:app` 방식으로 실행했습니다. 기존 8001 서비스와의 충돌을 피하고 Java 실행 옵션으로 새 포트를 지정했습니다. `--reload`는 원본 파일을 수정하지 않는 실행 검증에 필요하지 않아 사용하지 않았습니다.

재실행: PowerShell에서 `& 'C:\yw\login\gt-integration\example-final\Start-Example.ps1'`.

로컬 DB·Redis와 가상환경이 준비된 이 PC 기준 스크립트입니다. 설정·로그·검증 결과와 백업은 `C:\yw\login\gt-integration\example-final`에 있습니다. `runtime-env.json`에는 로컬 실행 비밀 설정이 있으므로 Git·공유 대상에서 제외해야 합니다. 이 파일은 프론트 및 프로젝트 저장소 밖에 두었습니다.
